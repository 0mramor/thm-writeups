## Что изучил
Как безопасность операционной системы ломается из-за человеческого фактора: слабые пароли, пароли в истории команд, чрезмерные привилегии.

## Ход прохождения
1. Подключился к удалённой машине по SSH: `ssh USER@IP`
2. Вошёл под пользователем `sammie`: пароль был написан на стикере рядом с экраном (пример физической небезопасности)
3. Для пользователя `johnny` подобрал пароль по списку самых популярных паролей: он оказался из этого списка
4. Под `johnny` выполнил `history`: там нашёлся пароль root, который пользователь по ошибке ввёл как команду
5. Переключился на root командой `su - root`
6. Прочитал флаг в домашней папке root через `cat`

## Команды
| Команда | Назначение |
|---|---|
| `ssh USER@IP` | подключиться к удалённой машине |
| `history` | показать историю введённых команд |
| `su - root` | переключиться на другого пользователя (root) |
| `cat` | вывести содержимое файла |
| `find` | поиск файлов |

## Выводы
- Слабые и популярные пароли подбираются за секунды
- Пароли нельзя записывать на стикерах и хранить в открытом виде
- Ввод пароля вместо команды сохраняется в `history`, и любой, кто зайдёт под этим аккаунтом, его увидит
- Принцип наименьших привилегий: доступ к одному слабому аккаунту не должен вести к root
- При вводе SSH-пароля символы на экране не отображаются: это нормально
