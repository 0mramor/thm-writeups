# TryHackMe: Linux Fundamentals

## Part 1
Комната знакомит с терминалом Linux: базовые команды, навигация по файловой системе, поиск файлов и операторы оболочки. Работа идёт в браузере через AttackBox / Split View.

### Коротко о Linux

- Linux — семейство ОС на одном ядре; популярные дистрибутивы: Ubuntu, Debian, Fedora.
- Используется на серверах, в веб-инфраструктуре, встраиваемых устройствах и в ИБ-инструментах (Kali, Parrot).
- Основной способ работы на серверах — терминал, поэтому команды нужно знать наизусть.

### Первые команды

| Команда | Что делает | Пример |
|---|---|---|
| `echo` | выводит текст в терминал | `echo Hello` |
| `whoami` | показывает текущего пользователя | `whoami` |

### Навигация по файловой системе

| Команда | Что делает | Пример |
|---|---|---|
| `ls` | список файлов и папок в текущем каталоге | `ls` |
| `cd` | переход в другой каталог | `cd /var/log` |
| `cat` | выводит содержимое файла | `cat file.txt` |
| `pwd` | показывает текущий путь | `pwd` |

### Поиск файлов

| Команда | Что делает | Пример |
|---|---|---|
| `find` | ищет файлы по имени, типу, пути | `find / -name "*.txt"` |
| `grep` | ищет текст внутри файла | `grep "word" file.txt` |

Заметки:
- Символ `*` (wildcard) заменяет любое количество символов: `*.txt` — все текстовые файлы.
- `grep` удобно применять к большим файлам, например к логам, чтобы быстро найти нужную строку.

### Операторы оболочки

| Оператор | Что делает |
|---|---|
| `&` | запускает команду в фоне |
| `&&` | выполняет вторую команду, только если первая завершилась успешно |
| `>` | перенаправляет вывод в файл (перезаписывает файл) |
| `>>` | дописывает вывод в конец файла |

Примеры:

```bash
echo hello > file.txt      # создаст или перезапишет file.txt
echo world >> file.txt     # допишет строку в конец
cd /tmp && ls              # ls выполнится, только если cd прошёл успешно
```

### Итоги

- Освоил базовый набор команд для работы в терминале: `echo`, `whoami`, `ls`, `cd`, `cat`, `pwd`, `find`, `grep`.
- Разобрал операторы `&`, `&&`, `>`, `>>` для комбинирования команд и работы с выводом.

## Part 2

Вторая часть углубляется в работу с файлами, пользователями и правами доступа. Работа идёт на машине в браузере (AttackBox / Split View).

### Что разбирается в комнате

- Подключение к удалённой машине по SSH
- Флаги (опции) команд и справка через `man`
- Работа с файлами: `touch`, `mkdir`, `cp`, `mv`, `rm`, `file`
- Пользователи и привилегии: `su`, `sudo`
- Права доступа к файлам и каталогам
- Типичные каталоги Linux

### Команды для работы с файлами

| Команда | Что делает | Пример |
|---|---|---|
| `touch` | создаёт пустой файл | `touch note` |
| `mkdir` | создаёт каталог | `mkdir folder1` |
| `cp` | копирует файл | `cp note Documents` |
| `mv` | перемещает или переименовывает файл | `mv note1 Documents` |
| `rm` | удаляет файл | `rm note` |
| `file` | определяет тип файла | `file note` |

Для `cp` нужны два аргумента: что копируем и куда. Без второго аргумента будет ошибка `missing destination file operand`.

### su и sudo

- `su user2` переключает на другого пользователя в текущем терминале, спросит пароль этого пользователя.
- `su -` загружает окружение нового пользователя (его домашний каталог и переменные).
- `su` без имени переключает на `root`.
- `sudo команда` выполняет одну команду с правами администратора и просит пароль текущего пользователя.
- Вернуться обратно можно командой `exit`.

### Права доступа

Права файла смотрят командой `ls -la`. Вывод вида `-rw-r--r--` читается так: тип, затем три тройки `rwx` для владельца, группы и всех остальных.

### Что получилось на практике

- Больше всего пригодились `cd` и `cat`: без навигации и чтения файлов остальные задания просто не сдвинуть с места.
- Флаг в каталоге `user2` удалось найти без `su`, просто пройдя в его домашний каталог через `cd`. Это возможно, когда каталог и файл открыты на чтение для «остальных» пользователей. Права я тогда не проверял, так как не знал про `ls -la`.
- Самостоятельно экспериментируя, удалил исходный `note` командой `rm`, поэтому пришлось перезапускать машину, чтобы вернуть файлы в исходное состояние.

### Итоги и выводы

- Освоил создание, копирование, перемещение и удаление файлов.
- Разобрал разницу между `su` и `sudo`, хотя `su` ещё стоит потренировать.
- Главный урок: перед тем как гулять по системе, смотреть права через `ls -la`, это быстро показывает, что открыто, а что нет.
- Осторожно с `rm`: удаление в Linux не уходит в корзину.

## Part 3

Третья часть посвящена процессам, фоновым задачами, простым сервисам и системным журналам. Самая насыщенная часть из трёх, есть над чем вернуться повторно.

### Фоновые задачи и `&`

Команда, запущенная в обычном режиме (foreground), занимает терминал полностью: пока она работает, вы не можете вводить другие команды в этом же окне.

```bash
python3 -m http.server      # занимает терминал, пока не остановить Ctrl+C
python3 -m http.server &    # запускается в фоне, терминал свободен сразу
```

**Важный урок:** если нужно запустить что-то (например, HTTP-сервер) и параллельно выполнить другую команду (например, `wget`), либо открывайте новое окно терминала, либо добавляйте `&` в конце первой команды.

### Процессы: `ps`, `top`, `kill`

| Команда | Что делает |
|---|---|
| `ps` | список процессов текущей сессии |
| `ps aux` | полный список всех процессов в системе |
| `top` | живой монитор процессов, обновляется в реальном времени |
| `kill PID` | завершает процесс по его номеру (PID) |

### systemctl и сервисы

Сервис — это процесс, которым управляет система (например, SSH-сервер, веб-сервер). Управляется через `systemctl`:

| Команда | Что делает |
|---|---|
| `systemctl start имя` | запускает сервис прямо сейчас |
| `systemctl stop имя` | останавливает сервис |
| `systemctl enable имя` | включает автозапуск сервиса при загрузке системы |
| `systemctl status имя` | показывает состояние сервиса |

Важно не путать `start` (запуск сейчас) и `enable` (автозапуск при следующей загрузке) — это разные действия, и в заданиях их специально разделяют.

### cron и `crontab`

`cron` — планировщик задач, который запускает команды по расписанию. Своё расписание пользователя смотрят командой:

```bash
crontab -l
```

Формат строки: **минута час день_месяца месяц день_недели команда**. Например:

```
0 */12 * * * cp -R /home/user/Documents /var/backups/
```

читается как «в 0 минут каждого часа, который делится на 12» → запуск в 00:00 и в 12:00 каждый день.

**Отдельный урок:** `@reboot` — это не расписание по времени, а специальное ключевое слово, заменяющее все пять полей сразу. Означает «запустить один раз при каждой загрузке системы», а не в конкретное время суток. На это легко попасться, если машинально искать часы и минуты там, где их просто нет.

### Логи системы

Логи лежат в `/var/log`. У каждой программы обычно свой файл или подпапка, например `/var/log/apache2/` для веб-сервера Apache:

| Файл | Что в нём |
|---|---|
| `access.log` | кто и что запрашивал на сайте (IP, путь, время) |
| `error.log` | ошибки сервера (часто недоступен обычному пользователю — `Permission denied`) |
| `*.log.N.gz` | старые логи, сжатые архивом (архивы через `cat` не читаются, нужен `zcat`) |

**Собственная ошибка, которую стоит запомнить:** после `cd ..` легко забыть, в какой вы папке, и команды типа `cat access.log` перестают находить файл, хотя он точно есть, просто в другой директории. Если сомневаетесь, где находитесь — `pwd` покажет точный путь.

### Что получилось на практике

- Главная путаница: foreground-процесс блокирует терминал, пока не завершится. Решение — `&` или второе окно.
- `@reboot` в crontab сломал привычную логику «расписание = время», оказалось, что это отдельный случай без конкретного времени.
- Потерял текущую директорию после `cd ..` и не смог найти файл логов, хотя он был на месте, просто в другой папке.

### Итоги

- Понял разницу между запуском процесса в foreground и background.
- Разобрался с `systemctl` (start vs enable) и базовым чтением `crontab`, включая специальный случай `@reboot`.
- Научился искать логи сервисов в `/var/log` и читать записи `access.log`.
- Усвоил не всё с первого раза, особенно процессы и cron — стоит вернуться и повторить это отдельно.
